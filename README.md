# Бот-администратор автомойки (aiogram 3 + Google Sheets + OpenRouter)

Telegram-бот, который играет роль ИИ-администратора: клиент пишет обычным текстом,
бот уточняет автомобиль, подбирает услугу или тариф, называет точную цену,
предлагает свободное время и записывает клиента — строка сразу появляется в Google-таблице.

Главный принцип: **нейросеть ничего не знает про цены и расписание «из головы»**.
У неё есть инструменты (tool calling), которые читают таблицу, считают стоимость и пишут запись.
Цены и свободные слоты считает код (`sheets.py`), поэтому модель не может ошибиться в сумме
или записать двоих на один слот.

---

## 1. Схема работы

```
                Telegram                        OpenRouter (LLM)                 Google Sheets
               ┌─────────┐    сообщение     ┌──────────────────┐   tools    ┌───────────────┐
  Клиент ─────►│ bot.py  │─────────────────►│  ai.py (Agent)   │───────────►│ sheets.py     │
               │ aiogram │◄─────────────────│  системный       │◄───────────│ (Store)       │
               └─────────┘   ответ модели   │  промпт + история│  результат │  прайс        │
                    ▲                       └──────────────────┘  функций   │  тарифы       │
                    │ уведомление админу            ▲                      │  слоты        │
                    └───────────────────────────────┼──────────────────────┤  записи       │
                                                    └──── цены/слоты считает КОД └───────────────┘
```

Поток данных при одном сообщении клиента:

1. `bot.py` принимает сообщение (aiogram, только личные чаты) и передаёт его в `Agent.reply()`.
2. `ai.py` собирает промпт: системное описание администратора (имя мойки, дата/время, правила) + история диалога.
3. Запрос уходит в модель через OpenRouter (OpenAI-совместимый API).
4. Если модель решает вызвать инструмент (например, «посчитай цену») — `ai.py` выполняет его в `sheets.py` и возвращает модели результат. Цикл повторяется максимум 6 шагов (`MAX_TOOL_STEPS`).
5. Модель формирует финальный текст — `bot.py` отправляет его клиенту (разбивая на части под лимит Telegram).
6. При создании/отмене записи бот дополнительно уведомляет администратора (`ADMIN_CHAT_ID`).

### Модули и их роли

| Файл | Назначение |
|---|---|
| `bot.py` | aiogram: приём сообщений, кнопка телефона, команды `/start`, `/reset`, уведомления |
| `ai.py` | диалог с моделью через OpenRouter, описание 6 инструментов, системный промпт, история диалогов |
| `sheets.py` | Google Sheets и **вся бизнес-логика**: прайс, тарифы, слоты, запись/отмена |
| `setup_sheet.py` | разовое создание листов-шаблонов с примерами в вашей таблице |
| `config.py` | чтение настроек из `.env` в объект `Config` |
| `run.py` | запуск с проверкой окружения и автоперезапуском при сбоях |
| `start.bat` | запуск на Windows: создаёт `.venv`, ставит зависимости, вызывает `run.py` |

## 2. Принцип работы алгоритма

### 2.1. Агент с инструментами (tool calling)

Модели в `ai.py` (`TOOLS`) доступны шесть функций:

| Инструмент | Что делает | Где считает |
|---|---|---|
| `get_price_list` | возвращает прайс: классы авто, услуги, тарифы, что убрано | `sheets.py` |
| `calculate_price` | точный расчёт суммы для класса авто (тариф + доп. услуги) | `sheets.py` |
| `get_free_slots` | свободное время (на 7 дней или на дату) | `sheets.py` |
| `create_booking` | создаёт запись в таблице — только после явного «да» клиента | `sheets.py` |
| `get_my_bookings` | предстоящие записи этого клиента (по Telegram ID) | `sheets.py` |
| `cancel_booking` | отмена записи по номеру (только своя и только будущая) | `sheets.py` |

Цикл `_run()` в `ai.py`: модель → вызовы инструментов → результаты в модель → … → финальный ответ.
Одно сообщение клиента — это от 2 до 7 запросов к модели.

Ключевая гарантия: **модель только выбирает, какой инструмент вызвать, и пересказывает результат**.
Арифметику, наличие услуг, занятость слотов и валидацию выполняет детерминированный код.

### 2.2. Расчёт цены (`Catalog.quote` в `sheets.py`)

1. Класс автомобиля (`Легковой`, `Кроссовер`, …) — это **заголовки колонок** листа «Услуги»
   между «Описание» и «Доступна». Модель относит марку клиента к классу по прайсу, код проверяет класс через `match_class`.
2. Тариф = сумма цен **доступных** услуг состава для класса минус скидка (`tariff_quote`).
   Если администратор убрал услугу («Доступна = нет») — тариф автоматически пересчитывается без неё,
   и в ответе помечается `not_included_now`, чтобы бот честно сообщил клиенту.
   Если убраны все позиции — тариф исчезает из предложений.
3. Доп. услуги добавляются построчно; услуга, уже входящая в тариф, второй раз не оплачивается (защита от дубля).
4. Пустая цена в колонке класса = услуга для этого класса не оказывается.

### 2.3. Слоты и защита от двойной записи

- Лист «Слоты»: одна строка = одно время начала, «Постов» — сколько машин принимается одновременно.
  Свободно = «Постов» − число активных записей на это время.
- Прошедшие слоты и слоты ближе `MIN_LEAD_MINUTES` не показываются и не бронируются.
- `create_booking` выполняется под блокировкой (`threading.RLock`) и **сбрасывает кэш** перед проверкой:
  слоты и записи читаются свежими, поэтому два клиента не получат один и тот же последний пост.
- Статус записи, начинающийся на «Отмен…» (например «Отменена»), освобождает слот.

### 2.4. Кэширование и лимиты API

| Данные | Кэш | Зачем |
|---|---|---|
| Прайс и тарифы | `CATALOG_CACHE_SEC` (по умолчанию 60 с) | лимит Google Sheets API ~60 запросов/мин |
| Слоты и записи | `SLOTS_CACHE_SEC` (по умолчанию 15 с) | лимит Google Sheets API ~60 запросов/мин |
| Перед записью/отменой | кэш сбрасывается | видеть актуальную занятость |

Диалоги хранятся в памяти процесса (последние `MAX_HISTORY` сообщений, по умолчанию 24).
Сообщения одного клиента обрабатываются по очереди (`asyncio.Lock`), синхронный код gspread
не блокирует событийный цикл (`asyncio.to_thread`).

## 3. Установка и запуск

Нужен Python 3.10+.

```bash
pip install -r requirements.txt
cp .env.example .env        # заполните значения (см. раздел 4)
python setup_sheet.py       # (один раз) создаст листы-шаблоны в вашей таблице
python bot.py
```

На Windows достаточно запустить `start.bat` — он сам создаст виртуальное окружение `.venv`,
установит зависимости и вызовет `run.py`.

**Рекомендуемый способ запуска — `python run.py`**: он проверит версию Python, наличие
`.env`, `credentials.json`, установленных пакетов и обязательных настроек, а затем будет
перезапускать бота через 5 секунд, если тот упадёт. Остановка — Ctrl+C.

Для постоянной работы на сервере используйте systemd или Docker.

### 3.1. Настройка Telegram

1. Создайте бота у [@BotFather](https://t.me/BotFather) — токен в `BOT_TOKEN`.
2. Свой Telegram ID (для `ADMIN_CHAT_ID`) узнайте у @userinfobot.

### 3.2. Настройка Google Sheets API

1. [console.cloud.google.com](https://console.cloud.google.com) → создайте проект →
   **APIs & Services → Library → Google Sheets API → Enable**.
2. **IAM & Admin → Service Accounts → Create** → вкладка **Keys → Add key → JSON**.
   Сохраните файл как `credentials.json` рядом с ботом.
3. Создайте Google-таблицу, нажмите **«Поделиться»** и дайте доступ **Редактора**
   адресу `client_email` из `credentials.json`.
4. Id таблицы (часть ссылки между `/d/` и `/edit`) — в `SPREADSHEET_ID`.

### 3.3. Настройка OpenRouter

1. Ключ с [openrouter.ai/keys](https://openrouter.ai/keys) — в `OPENROUTER_API_KEY`.
2. Модель — в `OPENROUTER_MODEL`. Она **обязана поддерживать tool calling**
   (на openrouter.ai/models включите фильтры `tools` и `free`), иначе бот не сможет читать таблицу.

Бесплатные модели имеют суффикс `:free`, например:
`google/gemma-4-31b-it:free`, `nvidia/nemotron-3-super-120b-a12b:free`,
`minimax/minimax-m3.1-flash:free`, `thinkingmachines/inkling:free`.
Состав бесплатных периодически меняется — сверяйтесь со списком моделей.

Учтите лимиты бесплатного тарифа OpenRouter: ~20 запросов/мин и 50 запросов/день
(1000/день, если вы хоть раз пополнили баланс на $10). Одно сообщение клиента —
это от 2 до 7 запросов к модели.

## 5. Работа с таблицей (инструкция администратора)

`setup_sheet.py` создаёт всё сам. Названия колонок можно писать в любом регистре.
Названия листов меняются через `.env` (см. `SHEET_*`).

### Лист «Услуги» — цены по габаритам

| Услуга | Описание | Легковой | Кроссовер | Внедорожник/минивэн | Доступна |
|---|---|---|---|---|---|
| Мойка кузова | Бесконтактная мойка | 700 | 800 | 1000 | да |
| Горячий воск | Защитное покрытие | 500 | 600 | 800 | **нет** |

* Колонки между «Описание» и «Доступна» — **классы автомобилей**. Названия и количество любые:
  добавили колонку «Микроавтобус» — бот сразу начнёт её учитывать. ИИ сам относит модель клиента к классу.
* Пустая цена в колонке класса = услуга для этого класса не оказывается.
* **«Доступна» = нет** — администратор «убрал» услугу: бот её не предлагает и не записывает.

### Лист «Тарифы» — комплексы услуг

| Тариф | Состав | Скидка % | Доступен |
|---|---|---|---|
| Стандарт | Мойка кузова, Пылесос салона, Протирка салона | 10 | да |

* «Состав» — названия услуг с листа «Услуги» через запятую.
* **Цена тарифа = сумма цен входящих услуг для класса авто минус скидка.**
  Если услуга убрана, тариф пересчитывается без неё автоматически, и бот честно говорит клиенту:
  «Сейчас в тариф не входит воск, цена — 1 395 ₽». Если убраны все позиции — тариф исчезает.
* «Доступен = нет» скрывает тариф целиком.

### Лист «Слоты» — когда можно записаться

| Дата | Время | Постов |
|---|---|---|
| 22.10.2026 | 10:00 | 2 |

* Одна строка = одно время начала. «Постов» — сколько машин можно принять одновременно.
* Чтобы закрыть время (обед, ремонт, выходной) — поставьте `0` или удалите строку.
* Свободно = «Постов» минус активные записи на это время. Прошедшие слоты и слоты ближе
  `MIN_LEAD_MINUTES` не показываются.
* Новые дни добавляйте строками (формат даты `ДД.ММ.ГГГГ`).

### Лист «Записи» — сюда бот пишет клиентов

`ID, Создано, Дата, Время, Имя, Телефон, Автомобиль, Класс, Тариф, Доп. услуги, Состав, Сумма, Комментарий, Telegram ID, Username, Статус`

* Статус при создании — «Новая». Меняйте как угодно («Подтверждена», «Выполнена»).
  Статус, начинающийся на **«Отмен…»**, освобождает слот.
* Порядок колонок можно менять, главное — не переименовывать их (бот ищет их по названию).

## 6. Что умеет бот (инструкция для клиента)

* консультирует по услугам и тарифам, определяет класс авто по марке/модели;
* называет цену с учётом убранных позиций;
* показывает свободное время, понимает «завтра», «в субботу вечером»;
* перед записью повторяет детали и ждёт подтверждения клиента;
* записывает в таблицу, не допускает двойной записи на один слот;
* клиент может спросить «какие у меня записи» и отменить запись;
* кнопка «Отправить номер телефона» — телефон попадает в запись;
* команды: `/start` — приветствие и сброс диалога, `/reset` — сброс диалога;
* уведомляет администратора в Telegram о новых записях и отменах (`ADMIN_CHAT_ID`).

## 7. Ограничения и заметки

* Одна запись занимает один слот. Если комплекс идёт дольше часа, делайте слоты реже
  (например, каждые 2 часа) или закрывайте следующий слот вручную.
* История диалогов хранится в памяти процесса — после перезапуска бот «забывает» разговоры
  (записи в таблице остаются).
* Лимит Google Sheets API — около 60 запросов/мин на сервисный аккаунт (смягчается кэшем,
  см. раздел 2.4).
* Запускайте **один** экземпляр бота: защита от двойной записи работает внутри одного процесса.
* Файлы `.env` и `credentials.json` содержат секреты — не публикуйте их и не коммитьте.
* Лимиты бесплатного OpenRouter: ~20 запросов/мин и 50/день (1000/день после пополнения на $10).

# Бот-администратор автомойки (aiogram 3 + Google Sheets + совместимый AI API)

Telegram-бот, который играет роль ИИ-администратора: клиент пишет обычным текстом,
бот уточняет автомобиль, подбирает услугу или тариф, называет точную цену,
предлагает свободное время и записывает клиента — строка сразу появляется в Google-таблице.

Главный принцип: **нейросеть ничего не знает про цены и расписание «из головы»**.
У неё есть инструменты (tool calling), которые читают таблицу, считают стоимость и пишут запись.
Цены и свободные слоты считает код (`sheets.py`); модель получает результаты инструментов.
Параллельные операции одного процесса выполняются под локальной блокировкой; внешние редакторы Sheets этой блокировкой не связаны.

---

## 1. Схема работы

```
                Telegram                          AI API (LLM)                  Google Sheets
               ┌─────────┐    сообщение     ┌──────────────────┐   tools    ┌───────────────┐
  Клиент ─────►│ bot.py  │─────────────────►│  ai.py (Agent)   │───────────►│ sheets.py     │
               │ aiogram │◄─────────────────│  системный       │◄───────────│ (Store)       │
               └─────────┘   ответ модели   │  промпт + история│  результат │  прайс        │
                    ▲                       └──────────────────┘  функций   │  тарифы       │
                    │ уведомление админу            ▲                      │  слоты        │
                    └───────────────────────────────┼──────────────────────┤  записи       │
                                                    └──── цены/слоты считает КОД └───────────────┘
```

Поток данных при одном сообщении клиента:

1. `bot.py` принимает сообщение (aiogram, только личные чаты) и передаёт его в `Agent.reply()`.
2. `ai.py` собирает промпт: системное описание администратора (имя мойки, дата/время, правила) + сведения клиента, состояние записи и история диалога.
3. Запрос уходит в настроенный OpenAI-совместимый Chat Completions API. Основной сервис и резервные задаются в `.env`.
4. Если модель решает вызвать инструмент (например, «посчитай цену») — `ai.py` выполняет его в `sheets.py` и возвращает модели результат. Цикл ограничен `AI_MAX_TOOL_ITERATIONS` (6) и `AI_MAX_TOOL_CALLS` (12).
5. Модель формирует финальный текст — `bot.py` отправляет его клиенту (разбивая на части под лимит Telegram).
6. При создании/отмене записи бот дополнительно уведомляет администратора (`ADMIN_CHAT_ID`).

### Модули и их роли

| Файл | Назначение |
|---|---|

| `admin.py` | уведомления администратору: лента диалогов «клиент → бот» и записи с кнопкой профиля |
| `sheets.py` | Google Sheets и **вся бизнес-логика**: прайс, тарифы, слоты, запись/отмена |
| `config.py` | чтение настроек из `.env` в объект `Config` |
| `run.py` | единая точка запуска: `.venv`, зависимости, проверка настроек, блокировка и перезапуск после сбоя |

## 2. Принцип работы алгоритма

### 2.1. Агент с инструментами (tool calling)

Модели в `ai.py` (`TOOLS`) доступны шесть инструментов работы с таблицей:

| Инструмент | Что делает | Где считает |
|---|---|---|
| `get_price_list` | возвращает прайс: классы авто, услуги, тарифы, что убрано | `sheets.py` |
| `calculate_price` | точный расчёт суммы для класса авто (тариф + доп. услуги) | `sheets.py` |
| `get_free_slots` | свободное время (на 7 дней или на дату) | `sheets.py` |
| `create_booking` | готовит предложение; запись выполняет Python после отдельного подтверждения | `ai.py` + `sheets.py` |
| `get_my_bookings` | предстоящие записи этого клиента (по Telegram ID) | `sheets.py` |
| `cancel_booking` | готовит отмену своей будущей записи; меняет статус после подтверждения | `ai.py` + `sheets.py` |

Кроме них, `respond` возвращает текст ответа и новые сведения клиента для памяти диалога.

Цикл `_run()` в `ai.py`: модель → вызовы инструментов → результаты в модель → … → финальный ответ.
Обычный ответ без инструментов — один запрос. Отдельная вычитка выключена по умолчанию.
Подтверждение готового предложения обрабатывается без модели; предельное число запросов зависит от настроек цикла и повторов.

Ключевая гарантия: **модель только выбирает, какой инструмент вызвать, и пересказывает результат**.
Арифметику, наличие услуг, занятость слотов и валидацию выполняет детерминированный код.

### 2.2. Расчёт цены (`Catalog.quote` в `sheets.py`)

1. Класс автомобиля (`Легковой`, `Кроссовер`, …) — это **заголовки колонок** листа «Услуги»
   между «Описание» и «Доступна». Модель относит марку клиента к классу по прайсу, код проверяет класс через `match_class`.
2. Тариф = сумма цен **доступных** услуг состава для класса минус скидка (`tariff_quote`).
   Если администратор убрал услугу («Доступна = нет») — тариф автоматически пересчитывается без неё,
   и в ответе помечается `not_included_now`, чтобы бот честно сообщил клиенту.
   Если убраны все позиции — тариф исчезает из предложений.
3. Доп. услуги добавляются построчно; услуга, уже входящая в тариф, второй раз не оплачивается (защита от дубля).
4. Пустая цена в колонке класса = услуга для этого класса не оказывается.

### 2.3. Слоты и защита от двойной записи

- Лист «Слоты»: одна строка = одно время начала, «Постов» — сколько машин принимается одновременно.
  Свободно = «Постов» − число активных записей на это время.
- Прошедшие слоты и слоты ближе `MIN_LEAD_MINUTES` не показываются и не бронируются.
- `create_booking` выполняется под блокировкой (`threading.RLock`) и **сбрасывает кэш** перед проверкой:
  слоты и записи читаются свежими. Это защищает клиентов одного процесса; другой компьютер или человек может изменить таблицу между проверкой и записью.
- Статус записи, начинающийся на «Отмен…» (например «Отменена»), освобождает слот.

### 2.4. Кэширование и лимиты API

| Данные | Кэш | Зачем |
|---|---|---|
| Прайс и тарифы | `CATALOG_CACHE_SEC` (по умолчанию 60 с) | снижение числа запросов Google Sheets |
| Слоты и записи | `SLOTS_CACHE_SEC` (по умолчанию 15 с) | лимит Google Sheets API ~60 запросов/мин |
| Перед записью/отменой | кэш сбрасывается | видеть актуальную занятость |

В памяти хранятся последние `AI_RECENT_TURNS` пар реплик (4), не больше `MAX_HISTORY` сообщений
и `AI_HISTORY_CHARS` символов (6000), плюс сведения клиента отдельно от проверенных цен и слотов.
История сокращается целыми парами; текущая последовательность вызовов/результатов инструментов не разрывается.
Сообщения одного клиента обрабатываются по очереди (`asyncio.Lock`), синхронный код gspread
не блокирует событийный цикл (`asyncio.to_thread`).
Быстрые сообщения объединяются перед обращением к AI (`REPLY_BATCH_SEC`, 0,4 с).
Повторные чтения в одной реплике используют уже полученный результат; связанные диапазоны
Sheets читаются пакетами. Перед изменением записи данные проверяются заново.

## 3. Установка и запуск

Нужен Python 3.10+ с поддержкой `venv` и `pip`. Скрипты не ставят системные пакеты.
На CachyOS/Arch используйте системный Python; на других дистрибутивах может понадобиться
пакет поддержки `venv` из репозитория дистрибутива. На Windows 10/11 установите Python
с python.org и включите добавление Python в PATH либо Python Launcher `py`.

Linux, включая CachyOS:

```bash
./start.sh --setup-only
# Сохраните свой .env и credentials.json в папке проекта.
./start.sh --check --no-install
./start.sh
```

Windows (cmd):

```bat
start.bat --setup-only
rem Сохраните свой .env и credentials.json в папке проекта.
start.bat --check --no-install
start.bat
```

Обе оболочки работают из любого текущего каталога. `run.py` создаёт `.venv` и переходит
на её интерпретатор. Зависимости устанавливаются при первом запуске, изменении
`requirements.txt`, версии Python или отсутствии нужного пакета. При неизменном окружении
повторного обращения к pip нет. `--no-install` запрещает установку. Не переносите `.venv`
между Windows/Linux и разными версиями Python; создавайте окружение на каждой машине.

Настройки берутся из существующего `.env` или переменных окружения; переменные окружения
имеют приоритет. Если `.env` ещё нет, создайте его по параметрам раздела 4.
Файл `.env.example` для запуска не нужен. Существующие ключи и токены сохраните.

`--check` проверяет файлы и настройки без подключения к Telegram, Sheets или AI;
проверка валидности ключей на сервере в этот режим не входит. При первом вызове оболочки
могут скачиваться зависимости; с `--no-install` сетевой установки нет.
Ошибка установки прекращает запуск. Файл ключа проверяется как JSON сервисного аккаунта;
криптографическую исправность и права Google подтверждает только реальное подключение.
Можно запускать напрямую: `python3 run.py` (Windows: `python run.py`).

`run.py` запускает `bot.py` дочерним процессом и перезапускает его после аварийного выхода.
Остановка: Ctrl+C, на Linux также SIGTERM; сигнал передаётся боту, клиенты Telegram и AI
закрываются. Незавершённый запрос Google может ждать сетевой тайм-аут.
ОС снимает блокировку при завершении процесса.
Блокировка использует ID бота в общем временном каталоге и защищает локальные копии
проекта в той же среде пользователя. Другой компьютер, отдельный контейнер или иной
временной каталог этой блокировкой не охвачены.

### 3.1. Настройка Telegram

1. Создайте бота у [@BotFather](https://t.me/BotFather) — токен в `BOT_TOKEN`.
2. Свой Telegram ID (для `ADMIN_CHAT_ID`) узнайте у @userinfobot.

### 3.2. Настройка Google Sheets API

1. [console.cloud.google.com](https://console.cloud.google.com) → создайте проект →
   **APIs & Services → Library → Google Sheets API → Enable**.
2. **IAM & Admin → Service Accounts → Create** → вкладка **Keys → Add key → JSON**.
   Сохраните файл как `credentials.json` рядом с ботом.
3. Создайте Google-таблицу, нажмите **«Поделиться»** и дайте доступ **Редактора**
   адресу `client_email` из `credentials.json`.
4. Id таблицы (часть ссылки между `/d/` и `/edit`) — в `SPREADSHEET_ID`.

### 3.3. Настройка AI API

1. Адрес API, ключ и модель задайте в `LLM_BASE_URL`, `LLM_API_KEY` и `LLM_MODEL`.
2. Модель **обязана поддерживать tool calling**, иначе бот не сможет читать таблицу.
3. Второй ключ и резервные сервисы настройте по разделу 4.1.

Поддерживаются совместимые Chat Completions API, включая xKiro, APInex и Cloudflare Workers AI.
Модели и порядок переключения берутся из настроек; лимиты зависят от сервиса и аккаунта.

### 4.1. Переключение совместимого AI API

Основной API задаётся через `LLM_*`. Параметры `AI_*` позволяют явно переопределить
адрес, ключ и модель. Для другого сервиса укажите его URL Chat Completions и модель с инструментами:

```dotenv
AI_BASE_URL=https://адрес-провайдера/v1
AI_API_KEY=ваш-отдельный-ключ
AI_MODEL=идентификатор-модели
AI_TIMEOUT_SEC=60
AI_REASONING_EFFORT=
AI_REASONING_SUPPORTED=false
AI_MAX_OUTPUT_TOKENS=1024
AI_TOKEN_LIMIT_PARAMETER=max_tokens
```

Не вставляйте этот шаблон URL буквально. Ключ `LLM_API_KEY` не подставляется другому хосту:
для нового адреса обязательны явные `AI_API_KEY` и `AI_MODEL`. Удалённый адрес требует
HTTPS; HTTP разрешён только для localhost. Ключи не размещайте в URL.

`LLM_API_KEY_2` добавляет второй ключ основного сервиса с той же моделью.
Для остальных резервов задайте тройки `LLM_FALLBACK_1_BASE_URL`, `LLM_FALLBACK_1_API_KEY`,
`LLM_FALLBACK_1_MODEL`; доступны номера от 1 до 3. Порядок: основной API → второй ключ →
резервы по номеру. Клиенты переиспользуются. При временной недоступности или исчерпании
квоты запрос переходит к резерву; отказавший API пропускается до истечения `Retry-After`
или 60 секунд, если сервер не указал срок. Затем проверяется его восстановление.

| Переменная | Значение по умолчанию | Поведение |
|---|---|---|
| `AI_ENABLED` | `true` | `false`: без клиента/запросов AI, ответ о недоступности помощника; остальные настройки запуска сохраняются |
| `AI_BASE_URL` | из `LLM_BASE_URL` | URL API, без `/chat/completions` |
| `AI_API_KEY` / `AI_MODEL` | из `LLM_*` для того же сервиса | явные переопределения ключа и модели |
| `AI_TIMEOUT_SEC` | `60` | предел ожидания одного API с повторами |
| `AI_REQUEST_BUDGET_SEC` | `120` | общий бюджет одной генерации на цепочку API; по умолчанию два `AI_TIMEOUT_SEC` |
| `AI_REASONING_EFFORT` | пусто | параметр не передаётся; `none` или `low` задавайте только при документированной поддержке |
| `AI_REASONING_SUPPORTED` | `false` | требуется `true` для передачи любого уровня reasoning; это подтверждение оператора, не автоопределение |
| `AI_TEMPERATURE` | `0.3` | пустое значение полностью убирает параметр для несовместимых моделей |
| `AI_MAX_OUTPUT_TOKENS` | `1024` | не менее 512; лимит включает аргументы инструментов, а для некоторых моделей и reasoning |
| `AI_TOKEN_LIMIT_PARAMETER` | `max_tokens` | можно выбрать `max_completion_tokens`; для Cloudflare он выбирается автоматически |
| `AI_MAX_TOOL_ITERATIONS` / `AI_MAX_TOOL_CALLS` | `6` / `12` | предел запросов цикла / вызовов инструментов за реплику |
| `AI_REQUEST_RETRIES` | `1` | 0–2 повтора только запросов к модели при сетевой ошибке, 429 или 5xx; SDK-повторы отключены |
| `AI_RECENT_TURNS` / `AI_HISTORY_CHARS` | `4` / `6000` | целые пары реплик / бюджет символов истории и нового сообщения |
| `AI_PROOFREAD_ENABLED` | `false` | дополнительный запрос вычитки обычного ответа; предложения и квитанции не переписываются моделью |
| `AI_SESSION_TTL_SEC` / `AI_MAX_SESSIONS` | `3600` / `1000` | срок бездействия сессии в секундах / предел неактивных и сохранённых сессий; активный запрос не удаляется |
| `SHEETS_AI_BASE_URL` / `SHEETS_AI_API_KEY` / `SHEETS_AI_MODEL` | пусто | независимые переопределения для ручных подсказок по заголовкам |
| `SHEETS_AI_JSON_MODE` | `true` | можно убрать неподдерживаемый `response_format`; локальная проверка остаётся |

Mapping по умолчанию наследует адрес, ключ и модель диалога, но не reasoning. При другом
хосте `SHEETS_AI_BASE_URL` нужен отдельный `SHEETS_AI_API_KEY`. Его лимит ответа — 1500,
таймаут и имя параметра лимита общие. Ни запуск, ни обычные записи не вызывают mapping AI.

Неподдерживаемый параметр/переполнение контекста (400) не запускает слепой повтор с
другими опциями. Уточните настройки по документации выбранного сервиса. Пустой ответ,
обрезанный ответ (`finish_reason=length`) и некорректные аргументы не приводят к записи.
Обрезанный вызов инструмента требует увеличения лимита или сокращения запроса, а не
догадки о недостающих полях. Никакой модели не гарантируется поддержка всех расширений API.

### 4.2. Подтверждение и состояние диалога

`respond` возвращает ответ клиенту и изменения памяти в одном вызове модели. Python
принимает разрешённые поля с источником в словах клиента. Имя, телефон,
авто, исходная просьба, класс, тариф, услуги и время живут отдельно от четырёх пар истории.
Названия каталога проверяются; старые значения можно сохранить при добавлении новой услуги.
Разговорное обозначение автомобиля хранится дословно в `car`, распознанная модель — отдельно
в `car_model`. Для однозначного автомобиля AI выбирает класс из прайса; при неоднозначности
уточняет модель или кузов. Сомнительные значения остаются в `tentative`.
Ошибка отдельного поля памяти не должна блокировать обычный ответ; перед записью
проверяются все обязательные данные. Распознавание смысла зависит от модели.

В каждый запрос входят прежний компактный системный промпт, схемы инструментов,
`CUSTOMER` (сведения клиента, неуверенные варианты, недостающие поля), `STATE` (проверенные
цены/слоты и этап операции), до четырёх пар истории и текущая реплика. Телефон из памяти
заменён признаком `phone_known`; Python подставляет его в предложение самостоятельно.
Контактные номера скрываются в сохранённой короткой истории. Внутри текущего цикла остаются
только вызовы/результаты инструментов этой реплики. Запросов ради извлечения памяти нет.
Известные поля убираются из схемы `create_booking`, Python подставляет их из памяти;
полный валидатор по-прежнему проверяет все аргументы. Проверенные сведения не дублируются
в `STATE`, если тот же результат уже есть среди инструментов текущего запроса.
На следующей реплике они снова включаются: API не предполагается сохраняющим контекст.
В короткой истории предложение заменяется отметкой о показе, а его состав, цена и время
остаются в структурированном состоянии. Телефон скрывается также при Unicode-разделителях
и JSON-экранировании. Первое сообщение с новым телефоном нужно модели для извлечения.

Исправление меняет нужные поля. Смена автомобиля сбрасывает прежний класс, смена даты —
прежнее время; первое сообщение о дате или автомобиле не стирает сведения, названные раньше.
Новый выбор услуг отменяет старый расчёт; удалённые зависимые поля нельзя восстановить
из старой истории аргументами инструмента. Любое уточнение после предложения снимает его.
Python отклоняет аргументы, противоречащие памяти или не имеющие источника у клиента.
Обычный текстовый ответ допустим без обновления памяти. Ошибка формата обновления
может вызвать один запрос на исправление; обязательные данные проверяются перед записью.
Противоречивые обновления `facts`/`tentative`, повторяющиеся JSON-поля и нечисловые
константы отклоняются целиком. В одном сообщении более ранняя цитата не заменяет уже
принятое позднее исправление. Ошибка чтения помечает прежний снимок устаревшим;
занятое время сохраняется как недоступное, не как подтверждённая доступность.

Сессии разделены по Telegram ID. Память остаётся только в процессе: `/reset`, перезапуск,
час бездействия по умолчанию или вытеснение при лимите удаляют её. Фоновая очистка идёт раз
в минуту, также при обращениях. Активные и ожидающие своей очереди запросы защищены от очистки.
`calculate_price` хранит расчёт, а не согласие клиента; `get_free_slots` хранит ограниченный
снимок с моментом проверки. Предложение заново проверяет доступность и цену.

Ни вопрос о наличии, ни точная дата/время/услуга, ни первый вызов `create_booking`
не создают строку. Python показывает имя, телефон, авто/класс, состав, сумму и время.
Предложение действует 10 минут. Telegram-обработчик разрешает подтверждение только
после успешной отправки всех частей именно этого предложения; старый ответ отправки
не подтверждает новое предложение. Явное «Да, подтверждаю запись» выполняет запись
без AI; «Да, но другое время» снимает предложение и начинает уточнение. `/reset`
удаляет предложение и не позволяет позднему ответу модели восстановить его.

При подтверждении `Store` заново проверяет цену, состав, вместимость и записи.
Изменение даже при прежней итоговой сумме требует нового согласия. Отмена также требует
предложения и подтверждения; изменившиеся детали отмены отклоняются. Неизвестный
результат записи не повторяется автоматически: проверьте свои записи и журнал.
Повторное «да» после выполненной операции возвращает квитанцию Python без AI и записи.
Отмена ожидающего запроса не останавливает уже начатую синхронную запись: результат
считается неопределённым, автоматического повтора нет. После перезапуска профиль и
предложение не восстанавливаются; существующий журнал операций защищает от повтора
неопределённой записи, не сохраняя отдельный файл контактных данных клиента.
Это не изоляция от внешней правки после последнего чтения Sheets.

Одинаковые чтения в пределах одной реплики выполняются один раз; кэш не переносится
между репликами. `get_price_list(size_class=...)` возвращает цены только нужного класса.
Свежие данные для предложения и бизнес-проверок читаются одним `values_batch_get`
по проверенным областям; холодный снимок обнаружения используется в той же операции.
Снимок живёт только под блокировкой одной операции. Неполный ответ отклоняется, смена
шапки требует повторной проверки. Независимые финальные preflight, формулы и журнал
сохранены. Интервал проверки структуры независим от обновления обычных записей.

## 5. Работа с таблицей (инструкция администратора)

Ниже описан исходный формат для режима `SHEETS_ADAPTIVE_ENABLED=false`.
Адаптивный режим и ручные правила описаны в разделе 8.
Названия колонок можно писать в любом регистре.
Названия листов меняются через `.env` (см. `SHEET_*`).

### Лист «Услуги» — цены по габаритам

| Услуга | Описание | Легковой | Кроссовер | Внедорожник/минивэн | Доступна |
|---|---|---|---|---|---|
| Мойка кузова | Бесконтактная мойка | 700 | 800 | 1000 | да |
| Горячий воск | Защитное покрытие | 500 | 600 | 800 | **нет** |

* Колонки между «Описание» и «Доступна» — **классы автомобилей**. Названия и количество любые:
  добавили колонку «Микроавтобус» — бот сразу начнёт её учитывать. ИИ сам относит модель клиента к классу.
* Пустая цена в колонке класса = услуга для этого класса не оказывается.
* **«Доступна» = нет** — администратор «убрал» услугу: бот её не предлагает и не записывает.

### Лист «Тарифы» — комплексы услуг

| Тариф | Состав | Скидка % | Доступен |
|---|---|---|---|
| Стандарт | Мойка кузова, Пылесос салона, Протирка салона | 10 | да |

* «Состав» — названия услуг с листа «Услуги» через запятую.
* **Цена тарифа = сумма цен входящих услуг для класса авто минус скидка.**
  Если услуга убрана, тариф пересчитывается без неё автоматически, и бот честно говорит клиенту:
  «Сейчас в тариф не входит воск, цена — 1 395 ₽». Если убраны все позиции — тариф исчезает.
* «Доступен = нет» скрывает тариф целиком.

### Лист «Слоты» — когда можно записаться

| Дата | Время | Постов |
|---|---|---|
| 22.10.2026 | 10:00 | 2 |

* Одна строка = одно время начала. «Постов» — сколько машин можно принять одновременно.
* Чтобы закрыть время (обед, ремонт, выходной) — поставьте `0` или удалите строку.
* Свободно = «Постов» минус активные записи на это время. Прошедшие слоты и слоты ближе
  `MIN_LEAD_MINUTES` не показываются.
* Новые дни добавляйте строками (формат даты `ДД.ММ.ГГГГ`).

### Лист «Записи» — сюда бот пишет клиентов

`ID, Создано, Дата, Время, Имя, Телефон, Автомобиль, Класс, Тариф, Доп. услуги, Состав, Сумма, Комментарий, Telegram ID, Username, Статус`

* Статус при создании — «Новая». Меняйте как угодно («Подтверждена», «Выполнена»).
  Статус, начинающийся на **«Отмен…»**, освобождает слот.
* Порядок колонок можно менять, главное — не переименовывать их (бот ищет их по названию).

---

## 6. Что умеет бот (инструкция для клиента)

* консультирует по услугам и тарифам, уточняет неподтверждённый класс автомобиля;
* называет цену с учётом убранных позиций;
* показывает свободное время, понимает «завтра», «в субботу вечером»;
* показывает предложение и записывает только после явного подтверждения доставленных деталей;
* записывает в таблицу с проверкой занятости и блокировкой внутри процесса;
* клиент может спросить «какие у меня записи» и отменить запись;
* кнопка «Отправить номер телефона» — телефон попадает в запись;
* команды: `/start` — приветствие и сброс диалога, `/reset` — сброс диалога;
* уведомляет администратора в Telegram о новых записях и отменах (`ADMIN_CHAT_ID`).

## 7. Ограничения и заметки

* Одна запись занимает один слот. Если комплекс идёт дольше часа, делайте слоты реже
  (например, каждые 2 часа) или закрывайте следующий слот вручную.

* История диалогов хранится в памяти процесса — после перезапуска бот «забывает» разговоры
  (записи в таблице остаются).
* Квоты Google Sheets проверьте в своём Google Cloud-проекте; кэш снижает частоту запросов,
  но не отменяет квоты. Адаптивные операции не повторяют HTTP-записи автоматически.
* Запускайте **один** экземпляр бота: защита от двойной записи работает внутри одного процесса.
* Файлы `.env` и `credentials.json` содержат секреты — не публикуйте их и не коммитьте.
* Доступность и лимиты AI зависят от выбранных провайдера, модели и аккаунта; офлайн-тесты их не подтверждают.


## 8. Адаптивная Google Sheets

По умолчанию `SHEETS_ADAPTIVE_ENABLED=false`: действует прежнее чтение по `SHEET_*`,
логика тарифов и бронирования общая для обоих режимов. В адаптивном
режиме те же `Store` и `Catalog` получают данные через канонические русские имена полей.
Менять диалоговые промпты для подключения другой структуры не нужно.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `SHEETS_ADAPTIVE_ENABLED` | `false` | включить правила адаптивного чтения/записи |
| `SHEETS_DISCOVER_ON_START` | `false` | проверить структуру перед началом polling, с учётом интервала |
| `SHEETS_SCHEMA_CHECK_INTERVAL_HOURS` | `24` | интервал полной проверки структуры, положительное число часов |
| `SHEETS_AI_MAPPING_ENABLED` | `false` | разрешить отдельную команду AI-подсказок |
| `SHEETS_FORCE_SCHEMA_REFRESH` | `false` | принудительно проверить структуру при первом обращении текущего процесса |
| `SHEETS_MAPPING_FILE` | `.runtime/sheets-mapping.json` | локальный JSON правил; не публиковать |

При первом обращении без сохранённых правил Python проверяет листы, их ID и названия,
размеры, именованные диапазоны, объединения, заголовки в первых 20 строках и расположение
формул. Чтение значений и формул выполняется пакетами до 50 листов.
Строка с начальным `=` ещё не доказывает наличие формулы: для таких ячеек дополнительно
читается тип `userEnteredValue.formulaValue`, без сохранения выражений в mappings. Это локальный разбор:
полные таблицы не отправляются модели и не сохраняются в JSON. Очень большие листы
(более 1 000 000 выделенных ячеек на лист) требуют отдельного ограничения области;
автоматический анализ останавливается с ошибкой, а не обрезает данные молча.

Распознаются русские и английские варианты: `Дата`/`Booking date`, `Время`/`Start time`,
`Телефон`/`Phone`, `Telegram ID`/`TG_ID`, `Статус`/`Status` и другие словари в `ALIASES`.
Названия листов свободные; неоднозначные кандидаты не выбираются по имени автоматически.
Поддерживаются:

- Обычные таблицы записей/слотов с любым порядком колонок и заголовком не обязательно в первой строке.
- Дневные листы с полной датой в названии (`Записи 2026-10-23`, `23.10.2026`). Дата может отсутствовать в строках.
- Дата в отдельной ячейке — через ручное `date_source`.
- Прайс с колонками классов авто и длинный прайс `Услуга, Класс, Цена`, который правила сворачивают для `Catalog`.
  В матрице автоматически принимаются только известные названия классов из `KNOWN_PRICE_CLASSES`.
  Другие числовые колонки требуют ручного подтверждения: длительность, код или счётчик нельзя молча считать ценой.
  Известные служебные числовые колонки исключаются. Для нестандартного настоящего класса подтвердите `price_fields`
  через `--validate-mappings`; лишний столбец сначала удалите из `columns` и `price_fields`.
- Узкая сетка слотов: дата в названии листа, колонка времени, `Пост 1`/`Бокс 2`/`Bay 3`.
  Пусто, `свободно`, `free`, `open` означают свободную ячейку; прочие значения считаются занятыми.
  Этот режим доступен **только для чтения**: создание и отмена записей блокируются.
  Если те же брони одновременно есть в сетке и в журнале записей, свободное количество может быть занижено.

### 8.1. Сохранённые правила и ручная правка

После включения адаптивного режима:

```bash
./start.sh --refresh-schema
# Windows: start.bat --refresh-schema
```

Команда читает Google Sheets, сохраняет конфигурацию локально и не запускает Telegram.
Ей нужны настройки `SPREADSHEET_ID` и ключ Google; токены бота и AI для обычного
разбора не нужны. Код выхода `0` означает подтверждённое чтение, `2` — сохранены правила,
но нужна ручная проверка; `1` — ошибка запуска/подключения. Разрешение записи выводится отдельно.

В JSON есть `version`, `spreadsheet_id`, `regions`, `relationships`, `named_ranges`,
`checked_at`, общий `structural_fingerprint`, `validation_status`, `writes_enabled` и проблемы.
Каждая область содержит:

- `role`: `services`, `tariffs`, `slots` или `bookings`; `sheet_id` и `sheet_title`.
- `header_row`, `first_data_row`, необязательную `end_row`; номера строк и колонок начинаются с 1.
- `columns`: каноническое имя → номер колонки. Например, `"Телефон": 6` означает шестую колонку любого названия.
- `transforms`: для даты `date`, `date:%m/%d/%Y` либо `serial_date`; для времени `time` либо `serial_time`.
  Неверное значение отклоняется, без подмены явно выбранного формата другой локалью.
  Время вида `10:00 PM` автоматически не превращается в `10:00`.
- `date_source`: `null`, `{"title": true}` либо `{"cell": [1, 2]}` для даты из B1.
  После изменения шапки ссылка на отдельную ячейку требует повторной ручной проверки.
- `status_map`: внешнее значение → канонический статус; `write_statuses` задаёт внешние значения новой и отменённой записи.
- `price_fields` для колонок классов или `pivot_prices` для длинного прайса;
  `grid_columns` и `free_markers` описывают сетку.
- `permissions.read/write` и раздельную `validation.read/write`; структурный снимок и fingerprint.

Обязательного `layout_type` нет. Поведение задают правила извлечения.
`relationships` описывает связи записей со слотами по дате/времени и тарифов с услугами;
это существующие связи бизнес-логики, не произвольный язык объединения таблиц.

Для правки остановите локальный бот, сделайте копию JSON, исправьте только нужные
`columns`, границы, преобразования, статусы или разрешения. Затем выполните:

```bash
./start.sh --validate-mappings
```

Ручные изменения требуют этой проверки. Не меняйте вычисляемые `validation`,
`validated_rule`, `structure` и `fingerprint` вручную. Для неопознанного листа можно добавить
область по образцу обнаруженной с нужным `sheet_id` и `role`. Проверьте диапазон и даты.
Для создания/отмены нужны все поля записи из раздела 5, включая идентификатор клиента,
статус и цену; дата может приходить из `date_source`.
Цены принимаются без отрицательных значений и произвольного текста, с целой частью и
не более чем двумя десятичными знаками. Неоднозначные `1,000`/`1.000` отклоняются,
а не превращаются в цену 1. Автоматического определения валюты и разделителей тысяч нет. При неполном наборе возможно
чтение, но запись остаётся закрытой. Разрешения приложения не заменяют права сервисного
аккаунта Google. Отсутствие листа тарифов автоматически не считается отсутствием тарифов:
при намеренно пустом каталоге тарифов настройте пустую область с заголовками.

### 8.2. Изменения схемы и свежесть данных

Полная проверка запускается при обращении, если прошло 24 часа, либо при
`--refresh-schema`. Это не фоновый таймер: без обращений к таблице проверка не выполняется.
Вставленные, удалённые, переименованные и перемещённые колонки попадают в `last_changes`.
Точные прежние заголовки сохраняют связи при перемещении; известные синонимы позволяют
восстановить переименование. Незнакомое переименование требует ручного сопоставления.
Потеря обязательного поля блокирует чтение области; потеря необязательного поля записи
сохраняет безопасное чтение и закрывает запись. В прайсе потеря сопоставленной колонки,
включая доступность или скидку, блокирует чтение до ручной проверки. Иначе отключённая
услуга могла бы стать доступной, а скидка — исчезнуть. Блокировка сохраняется при дальнейших
изменениях структуры. Незатронутые связи сохраняются.
Новую колонку класса в существующем матричном прайсе подтвердите в `columns/price_fields`.

Интервал структуры **не относится к записям и слотам**. Их кэш остаётся `SLOTS_CACHE_SEC`
(15 секунд по умолчанию), а перед бронированием/отменой данные перечитываются.
Заголовки проверяются при каждом чтении данных; обнаруженный сдвиг немедленно вызывает
проверку структуры. Перед записью дополнительно проверяются формулы, объединения,
разрешения и идентичность текущего набора записей, цен и вместимости. Для этого используется
уже полученный пакет preflight, без отдельных повторных чтений каждого листа. Изменившееся
предложение отклоняется; перед записью проверяются последняя шапка и строки назначения.
Отмена сверяет все сопоставленные поля строки, включая статус. Поэтому запись делает
больше запросов, чем обычный просмотр. Прайс кэшируется по `CATALOG_CACHE_SEC`, а при бронировании читается заново.

### 8.3. AI-подсказки

Обычное обнаружение, запуск и изменения структуры не вызывают AI. При непонятной
семантике заголовков оператор может включить `SHEETS_AI_MAPPING_ENABLED=true` и выполнить:

```bash
./start.sh --suggest-mappings
```

В запрос уходят только несопоставленные заголовки проверенных строк шапки, роль, допустимые поля и
затронутые зависимости — без строк клиентов, телефонов, формул и значений записей.
Для нераспознанной шапки оператор может добавить `semantic_headers` в корень JSON:
`[{"sheet_id": 7, "role": "bookings", "header_row": 2, "headers": ["Номер", "Начало"]}]`.
Проверьте этот список сами: он должен содержать только заголовки, без персональных данных.
Не указывайте строки клиентов как `header_row`.

Подсказки сохраняются в соседнем `*-suggestions.json`, не применяются и не дают модели
доступа к записи. Для полностью распознанной схемы обращения к AI нет. Повторная команда с прежними заголовками не обращается к провайдеру.
После изменения колонки отправляются только новые/переименованные заголовки и их
зависимости; чистое перемещение разбирает Python. Используется настроенный совместимый API; отдельные `SHEETS_AI_*` могут переопределить адрес, ключ и модель.
Совместимость модели с JSON-ответом проверяется отдельно; `SHEETS_AI_JSON_MODE=false` убирает `response_format`, но проверка JSON в Python остаётся.
Ошибочный ответ отклоняется, текущие mappings не меняются. Повторное назначение поля,
несуществующие колонки, дробные номера колонок и попытки заменить уже подтверждённое
поле отклоняются. Семантическую правильность допустимой подсказки подтверждает человек.
Кэш привязан к ID таблицы; некорректный JSON даёт понятную ошибку. Ошибки провайдера и
лимиты не повторяются автоматически, их тело не выводится. После ошибки можно снова
вызвать команду явно.

### 8.4. Защита записи и ограничения

Создание меняет только сопоставленные ячейки одной новой пустой строки через RAW-обновление;
отмена меняет одну ячейку статуса после повторной проверки ID и Telegram ID.
Несопоставленные колонки, формулы и форматирование не переписываются.
При формулах в сопоставленных колонках записей или объединённых ячейках в области
запись блокируется. Пустые строки с формулами не используются как свободные.
Если выделенные строки закончились, расширьте область вручную.

Локальный `*-operations.json` хранит хеш операции, адрес строки и состояние, без текста
клиента. После неизвестного результата сетевой записи повтор того же запроса блокируется.
Журнал записывается атомарно с синхронизацией на диск; в Linux права файла — 0600.
Адаптивный клиент не использует автоматические HTTP-повторы записи: даже повтор того же
диапазона может затереть внешнюю правку. Остановите бот, вручную сверьте адрес из журнала с таблицей; только после сверки удаляйте
конкретную запись журнала или подтверждайте результат в таблице. Не удаляйте журнал
массово при работающем боте. Успешная отмена освобождает запись журнала для повторной брони.
Защита не является универсальной распределённой идемпотентностью.

Google Sheets не предоставляет здесь транзакционную изоляцию от внешних редакторов.
Человек или другой процесс может изменить запись между последней проверкой и HTTP-записью.
Для общей таблицы согласуйте одного владельца записей. Строгую распределённую гарантию
нужно строить вне Sheets. Локальная блокировка Telegram не заменяет блокировку таблицы
при разных ботах, записывающих в один документ.

Не поддерживаются автоматически: произвольные календари с объединениями и цветами,
расписания только по форматированию, несколько неоднозначных обычных журналов,
даты без года, неоднозначные локали дат без ручного формата, диаграммы и внешние DATA_SOURCE
листы. Несколько таблиц одной роли на одном листе требуют ручных ограниченных областей;
несколько обычных областей одной роли без `date_source` отклоняются. Две области одной
роли с одной датой также отклоняются, чтобы копия дневного листа не удвоила вместимость. ID записей должны быть
уникальными по всем дневным листам; локально повторяющиеся дневные номера требуют ручной
миграции/согласования. Длительность услуги по-прежнему не резервирует несколько слотов.

Секреты, `.venv`, кэши и `.runtime` исключены из Git. Для ключей с произвольным именем
добавьте собственное правило `.gitignore`. Не публикуйте локальные mappings: даже имена
листов и заголовков могут содержать внутреннюю информацию.

## 9. Локальная проверка

```bash
./start.sh --setup-only
python3 checks/run.py
# Настоящие интеграции, с расходом AI-квоты:
python3 checks/run.py --live
```

Windows: `start.bat --setup-only`, затем `python checks/run.py` или `python checks/run.py --live`.
Без флагов тесты изолированы: сеть запрещена, настоящие `.env` и ключи не загружаются.
`--live` читает Telegram и Sheets, проверяет AI-инструменты и диалог на каждом настроенном
ключе. Сообщения Telegram не отправляются, записи в Google не создаются; диалог использует
тестовое хранилище. При ошибке выводятся имя теста, файл и строка; `-v` показывает все проверки.
Папку `checks/` можно удалить целиком — запуск бота от неё не зависит.
Проверенные результаты и оставшиеся интеграционные проверки перечислены в TODO.md.

В журнал приложения не выводятся аргументы инструментов, тексты исключений провайдера
и сообщений администратору: сохраняются имя операции и тип ошибки. Логи `openai`, `httpx`,
`httpx2`, `httpcore` подавлены, включая установленный до запуска `OPENAI_LOG=debug`.
Сторонняя перенастройка логирования после запуска и другие SDK не покрыты этой защитой; не публикуйте журналы без просмотра.

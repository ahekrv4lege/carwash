# Изменения

- Обычный ответ AI больше не требует служебного вызова памяти. Ошибка отдельного
  необязательного поля не обрывает разговор; операции записи проверяются целиком.
- Слова клиента об автомобиле и распознанная модель разделены. Класс выбирается
  из фактического прайса, разговорные услуги сопоставляются с его названиями.
- Короткий контекст сохраняется в прежнем бюджете истории; расчёты используются
  повторно. Дни недели и время «в 11» распознаются без дополнительных AI-запросов.
- Приветствие сокращено, повторные обращения по имени убраны. Минимальное время
  ответа задаёт REPLY_MIN_DELAY_SEC=1.5; 0 отключает паузу. Время AI уже учитывается.
- Промпт сокращён, обязательный вопрос в каждой реплике убран. Исправлены цитаты
  автомобиля в падежах и дата/время, процитированные целым предложением.
- Состав тарифа не принимается за дополнительные услуги. Класс можно передать
  из прочитанного прайса без повторного сохранения памяти; ошибки указывают поле.
- Cloudflare получает системные сообщения в начале, актуальный параметр лимита
  ответа и явное отключение thinking по умолчанию у поддерживаемых моделей.
- Лишнее car_model не подменяет исходный автомобиль в записи. После исправления
  памяти отклонённое предложение проверяется повторно без нового AI-запроса.
- Модель и класс можно уточнить по уже сохранённому автомобилю, даже если последнее
  сообщение содержит телефон. Чужой автомобиль и отсутствующий в прайсе класс отклоняются.
- Локальная цепочка: Mistral Large 3 на двух ключах xKiro → MiniMax M3.1 Flash
  на APInex → Qwen 3.8 27B на Cloudflare. Ключи сохранены в .env вне Git.
- При обязательном respond отправляется только его схема вместо всех семи.
  Прайс и тарифы читаются одним пакетом; данные первичного разбора используются повторно.
- Неверная дата отклоняется до чтения слотов и записей из Google Sheets.
- Готовый заказ сразу направляется в create_booking: он сам проверяет цену и слот.
  В схеме обязательны только ещё не сохранённые данные клиента.
- Первый вопрос об услугах направляется к прайсу с одной схемой инструмента.
  Ошибка обязательного поля называет его и переводит модель к уточнению вместо повторов.
- Неверный класс без загруженного прайса направляется к get_price_list;
  сообщение об ошибке больше не требует, чтобы клиент сам назвал класс.
- В истории остаётся настоящее подтверждение с временем и ценой, без подмены
  служебной фразой, которую MiniMax копировала клиенту.
- Однозначные дата и время сохраняются без дополнительного AI-запроса;
  явный телефон сохраняется до скрытия в истории. Условия и неоднозначные варианты пропускаются.
- Исправление готового заказа открывает известные поля в схеме; конфликт указывает поле.
  Добавление услуги сохраняет тариф, а старый выбор не подставляется молча вместо последнего расчёта.
- Сбой Sheets завершает ответ без повторной генерации; известная цена после записи не требует нового прайса.
- Повторный результат инструмента передаётся AI короткой ссылкой на уже прочитанные данные.
  Слоты и записи читаются одним пакетом, данные первичного разбора используются повторно.
- Быстрые сообщения объединяются за REPLY_BATCH_SEC=0.4; 0 отключает объединение.
  Команды, контакты и подтверждения идут отдельно, ответы отправляются по порядку.
- Раннее согласие не подтверждает ещё не доставленное или изменившееся предложение.
  Ограничения API учитывают Retry-After; преждевременные повторы пропускаются.
- Явная смена тарифа сохраняется и при расчёте без respond. Просьба подготовить запись
  с полными данными получает предложение Python даже после обычного текстового ответа AI.
- Автомобиль из вопроса о прайсе сохраняется через обязательный ответ с памятью,
  без дополнительной генерации. Ошибки предположительных полей теперь указывают поле.
- Для уже распознанной модели AI может уточнить предположительный класс явным выбором
  из прайса. Сомнения в автомобиле/модели и личных данных по-прежнему блокируют предложение.
- Условия выбора тарифа и уточнения класса названы явно. Приём, объединение и доставка
  сообщений разделены внутри bot.py; правила, промпты и запросы к API не изменены.

Все 408 тестов прошли. Ранее проверили 101 ситуацию; в этом шаге — 12 живых сценариев
с повторами: 11 прошли, один выявил лишний вопрос о предположительном классе.

Синтаксис Python 3.10 проверен.

--live проверяет настоящие интеграции и расходует AI-квоту.
